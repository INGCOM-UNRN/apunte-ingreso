<!-- _header: '¿Qué son?' -->

# Diagramas de Flujo

**Definición:**
* Representación gráfica de un algoritmo
* Usa símbolos estandarizados
* Muestra el orden con flechas

**Ventaja:**
* Se visualiza el flujo de datos
* Fácil de entender y compartir
* Detectar errores antes de programar

<!--
**Definición clave:** Un diagrama de flujo es un algoritmo expresado visualmente mediante símbolos geométricos conectados por flechas.

**Estandarización:** Los símbolos están estandarizados por normas como ISO 5807 y ANSI. Esto significa que un diagrama de flujo hecho en Argentina se entiende igual en Japón o Estados Unidos.

**Ventajas prácticas:**
1. **Visualización del flujo:** Podés "caminar" por el algoritmo con el dedo siguiendo las flechas
2. **Colaboración:** Mostrá tu diagrama a alguien que no programa y lo entenderá
3. **Debugging preventivo:** Muchos bugs lógicos se detectan en el diagrama, donde son fáciles de corregir

**Analogía útil:** Un diagrama de flujo es como el plano de un edificio antes de construirlo. Es más barato cambiar el plano que demoler paredes.

Preguntá: "¿Alguien ya vio diagramas de flujo en otra materia?" (matemática, física, organización de empresas). Conectá con conocimiento previo.
-->

<!-- _header: 'Símbolos básicos' -->

# Símbolo: Inicio/Fin

**Óvalo:** Marca inicio y fin del algoritmo

```
    ╭─────────╮
    │ INICIO  │
    ╰─────────╯
```

```
    ╭─────────╮
    │   FIN   │
    ╰─────────╯
```

<!--
El **óvalo o elipse** representa los puntos de entrada y salida del algoritmo.

**Reglas importantes:**
- Todo diagrama debe tener EXACTAMENTE un INICIO
- Todo diagrama debe tener AL MENOS un FIN (puede haber múltiples puntos de finalización en casos complejos)
- INICIO nunca tiene flechas que entren, solo que salen
- FIN nunca tiene flechas que salen, solo que entran

**Nombres alternativos:** Algunos usan "Comienzo" y "Fin", otros "Start" y "Stop". Todos son válidos, pero mantené consistencia en tu proyecto.

**Error común:** Olvidar el INICIO o FIN. Un diagrama sin estos símbolos está incompleto y genera confusión sobre dónde empieza o termina la ejecución.

Podés compararlo con los paréntesis en matemática: siempre deben estar balanceados y en los lugares correctos.
-->

<!-- _header: 'Símbolos básicos' -->

# Símbolo: Entrada/Salida

**Paralelogramo:** Leer o mostrar datos

```
    ╱──────────╲
   ╱ Leer edad  ╲
  ╱──────────────╲
```

```
    ╱─────────────╲
   ╱ Mostrar suma  ╲
  ╱─────────────────╲
```

<!--
El **paralelogramo** representa operaciones de **entrada/salida** (input/output, I/O).

**Entrada (input):** Leer datos del usuario o de un archivo
- "Leer edad", "Ingresar nombre", "Obtener temperatura"

**Salida (output):** Mostrar información al usuario o escribir en archivo  
- "Mostrar suma", "Imprimir resultado", "Escribir mensaje"

**Correspondencia con Python:**
- Paralelogramo de entrada → `input()` en Python
- Paralelogramo de salida → `print()` en Python

**Convención:** Usá verbos claros:
- ✅ "Leer edad" o "Ingresar edad" para input
- ✅ "Mostrar resultado" o "Imprimir suma" para output
- ❌ "edad" (ambiguo: ¿leer o mostrar?)

**Tip pedagógico:** El paralelogramo representa "cruzar el límite" entre el programa y el mundo exterior (usuario, archivo, red, etc.).
-->

<!-- _header: 'Símbolos básicos' -->

# Símbolo: Proceso

**Rectángulo:** Operaciones y cálculos

```
  ┌──────────────────┐
  │ suma = a + b     │
  └──────────────────┘
```

```
  ┌──────────────────┐
  │ contador = 1     │
  └──────────────────┘
```

<!--
El **rectángulo** representa **operaciones internas**: cálculos, asignaciones, transformaciones de datos.

**Ejemplos típicos:**
- Asignaciones: `contador = 1`, `nombre = "Juan"`
- Cálculos: `suma = a + b`, `promedio = total / cantidad`
- Modificaciones: `edad = edad + 1`, `total = total + precio`

**Correspondencia con Python:**
- Rectángulo → Cualquier línea de código que NO sea input/output ni decisión ni lazo

**Sintaxis dentro del rectángulo:**
- Usá el símbolo `=` para asignación (como en Python)
- Podés usar notación matemática o pseudocódigo
- Mantené una línea por rectángulo (si hay múltiples operaciones relacionadas, considerá si deberían ser rectángulos separados)

**Error común:** Confundir proceso con entrada/salida. "Calcular suma" va en rectángulo; "Leer números" va en paralelogramo.

**Regla nemotécnica:** El rectángulo es para "pensar", el paralelogramo para "comunicarse".
-->

<!-- _header: 'Símbolos básicos' -->

# Símbolo: Decisión

**Rombo:** Preguntas con Sí/No

```
        ╱╲
       ╱  ╲
      ╱edad╲
     ╱ >=18?╲
    ╱────────╲
         │
    Sí ╱   ╲ No
```

**Siempre tiene 2 salidas**

<!--
El **rombo o diamante** representa una **decisión** o **condición**: una pregunta que tiene dos respuestas posibles.

**Características críticas:**
- **SIEMPRE tiene exactamente 2 salidas:** Sí (verdadero) y No (falso)
- La pregunta dentro debe ser **booleana** (respuesta Sí/No, Verdadero/Falso)
- **NO** puede tener 3 o más opciones (para eso se usan múltiples rombos)

**Correspondencia con Python:**
- Rombo → `if`, `elif`, `while` (cualquier estructura que evalúe una condición)

**Sintaxis dentro del rombo:**
- Escribí una condición clara: `edad >= 18?`, `x > 0?`, `nombre == "admin"?`
- El signo `?` es opcional pero ayuda a claridad
- Etiquetá CLARAMENTE las salidas: "Sí"/"No", "V"/"F", "Verdadero"/"Falso"

**Error común:** Olvidar etiquetar las salidas. Sin etiquetas, no está claro qué camino tomar.

**Analogía:** El rombo es una bifurcación en el camino. Debés elegir un camino u otro, nunca ambos simultáneamente.

Preguntá: "¿Qué pasa si la condición tiene 3 opciones?" (Respuesta: usás múltiples rombos encadenados).
-->

---

<!-- _header: 'Símbolos básicos' -->

# Símbolo: Flechas

**Conectores:** Muestran el orden

```
    ╭─────────╮
    │ INICIO  │
    ╰─────────╯
         │
         ↓
    ╱──────────╲
   ╱ Leer edad  ╲
  ╱──────────────╲
```

<!--
Las **flechas** (o líneas de flujo) conectan los símbolos y muestran el **orden de ejecución**.

**Dirección estándar:**
- **Arriba → Abajo:** Flujo principal siempre va hacia abajo
- **Izquierda → Derecha:** Flujos secundarios van hacia la derecha
- Evitá flujos que vayan hacia arriba EXCEPTO en lazos (donde es necesario)

**Convenciones:**
- La punta de flecha indica dirección (aunque en flujo vertical a veces se omite si es obvio)
- No cruces flechas (si es inevitable, usá "puentes" o conectores circulares)
- Mantené el diagrama limpio: flechas rectas cuando sea posible

**Correspondencia con ejecución:**
- Las flechas representan el "hilo de ejecución"
- Seguir las flechas es como ejecutar el programa paso a paso (debugging mental)

**Error común:** Diagramas con flechas que van en todas direcciones (caótico). Un buen diagrama fluye naturalmente de arriba hacia abajo.

**Tip de diseño:** Si tu diagrama tiene flechas que se cruzan mucho o van hacia arriba constantemente, probablemente necesites reorganizar los símbolos o replantear el algoritmo.
-->

---

<!-- _header: 'Reglas' -->

# Reglas de Diagramas

1. Siempre empezar con INICIO
2. Siempre terminar con FIN
3. Las flechas muestran el orden
4. Los rombos tienen 2 salidas: Sí y No
5. Escribir claro dentro de cada símbolo
6. No cruzar flechas

<!--
Estas son las **6 reglas de oro** para diagramas de flujo bien formados:

**1. Empezar con INICIO:** Todo diagrama necesita un punto de entrada claro. Sin INICIO, ¿dónde empieza la ejecución?

**2. Terminar con FIN:** Todo algoritmo debe tener condiciones de terminación. Un diagrama sin FIN sugiere un lazo infinito o lógica incompleta.

**3. Flechas muestran orden:** El orden de ejecución debe ser inequívoco. Si dos personas siguen tu diagrama, ambas deben llegar al mismo resultado.

**4. Rombos con 2 salidas:** NUNCA un rombo con una sola salida (sería inútil) o tres salidas (usá múltiples rombos).

**5. Escribir claro:** Evitá abreviaturas crípticas. "Leer n" es menos claro que "Leer número". El espacio dentro del símbolo es limitado, pero la claridad es prioritaria.

**6. No cruzar flechas:** Los cruces crean confusión visual. Si es inevitable, usá conectores circulares pequeños o reorganizá el diagrama.

**Consejo para enseñar:** Mostrá un diagrama que viole varias reglas y pedí que identifiquen los problemas. El aprendizaje por contraste es efectivo.
-->

# Sumar dos números

**Problema:**
* Pedir dos números
* Sumarlos
* Mostrar el resultado

**Diagrama:**
* Sin decisiones
* Sin lazos
* Flujo lineal simple

<!--
Este es el ejemplo más básico posible: **flujo secuencial** (o lineal). No hay bifurcaciones, no hay repeticiones, solo una secuencia de pasos que se ejecutan uno tras otro.

**Estructura del problema:**
- **Entrada:** Dos números
- **Proceso:** Sumarlos
- **Salida:** El resultado

**Propósito pedagógico:** Este ejemplo enseña la estructura básica antes de agregar complejidad. Todos los estudiantes pueden resolverlo mentalmente, así que se enfocan en aprender la notación, no en resolver el problema.

**Observá la estructura:** INICIO → Entrada1 → Entrada2 → Proceso → Salida → FIN. Esta secuencia aparecerá en casi todos los programas que escribirán.

En el siguiente slide mostraremos el diagrama completo. Antes de avanzar, podés preguntar: "¿Alguien puede describir los símbolos que necesitaremos?"

# Diagrama: Sumar dos números

```
    ╭─────────╮
    │ INICIO  │
    ╰─────────╯
         │
    ╱────────────╲
   ╱ Leer numero1 ╲
  ╱────────────────╲
         │
    ╱────────────╲
   ╱ Leer numero2 ╲
  ╱────────────────╲
         │
  ┌──────────────────┐
  │ suma = n1 + n2   │
  └──────────────────┘
         │
    ╱──────────╲
   ╱ Mostrar   ╲
  ╱    suma     ╲
 ╱──────────────╲
         │
    ╭─────────╮
    │   FIN   │
    ╰─────────╯
```

<!--
Acá está el diagrama completo. Caminemos por él paso a paso:

**1. INICIO (óvalo):** Punto de entrada del algoritmo

**2. Leer numero1 (paralelogramo):** Primera entrada. El usuario ingresa el primer número, que se almacena en la variable `numero1`

**3. Leer numero2 (paralelogramo):** Segunda entrada. El usuario ingresa el segundo número

**4. suma = n1 + n2 (rectángulo):** Proceso. Aquí realizamos el cálculo. Usé `n1` y `n2` como abreviaciones de `numero1` y `numero2` para que quepa en el símbolo (es aceptable cuando está claro)

**5. Mostrar suma (paralelogramo):** Salida. Mostramos el resultado al usuario

**6. FIN (óvalo):** Terminación del algoritmo

**Observaciones clave:**
- El flujo es vertical (arriba → abajo)
- No hay bifurcaciones
- Cada paso depende del anterior
- Los 4 tipos de símbolos básicos están representados

**Actividad sugerida:** Pedí a un voluntario que "ejecute" el diagrama con valores reales (ej: numero1=5, numero2=3). Que vaya diciendo cada paso en voz alta mientras señala el símbolo. Esto demuestra que el diagrama ES el algoritmo.

**Transición al código:** Este diagrama se traduce casi directamente a Python (próxima clase lo verán).
-->

# ¿Es mayor de edad?

**Problema:**
* Preguntar la edad
* Decir si es mayor o menor de edad

**Diagrama:**
* CON decisión (rombo)
* Sin lazos
* Dos caminos posibles

<!--
Este ejemplo introduce las **estructuras condicionales** (decisiones). Ahora el flujo NO es lineal: hay una bifurcación y dos caminos posibles.

**Estructura del problema:**
- **Entrada:** edad
- **Decisión:** ¿edad >= 18?
- **Salida (camino 1):** "Mayor de edad"
- **Salida (camino 2):** "Menor de edad"

**Diferencias con el ejemplo anterior:**
- Antes: todos ejecutaban los mismos pasos
- Ahora: dependiendo de la entrada, se ejecutan pasos diferentes

**Concepto clave:** El rombo representa el punto donde el flujo se bifurca. Solo UNO de los dos caminos se ejecutará en cualquier ejecución particular.

**Correspondencia con Python:** Este diagrama se traducirá a una estructura `if-else`.

**Pregunta para reflexionar:** "Si alguien tiene exactamente 18 años, ¿qué camino toma?" (Respuesta: el Sí, porque la condición es `>=18`, no `>18`). Esto muestra la importancia de ser preciso en las condiciones.

Avancemos al diagrama completo en el siguiente slide.
-->

# Diagrama: Mayor de edad

```
    ╭─────────╮
    │ INICIO  │
    ╰─────────╯
         │
    ╱──────────╲
   ╱ Leer edad  ╲
  ╱──────────────╲
         │
        ╱╲
       ╱  ╲
      ╱edad╲
     ╱ >=18?╲
    ╱────────╲
   Sí│      │No
     │      │
  Mostrar  Mostrar
   Mayor   Menor
     │      │
     └──┬───┘
        │
    ╭─────────╮
    │   FIN   │
    ╰─────────╯
```

<!--
Analicemos este diagrama con decisión:

**1. INICIO → Leer edad:** Igual que antes, comenzamos solicitando entrada

**2. Rombo (edad >= 18?):** Aquí está la **decisión**. La ejecución se bifurca:
   - Si edad es 18 o más → camino "Sí" (derecha)
   - Si edad es menor a 18 → camino "No" (izquierda)

**3. Camino Sí:** Mostrar "Mayor de edad"

**4. Camino No:** Mostrar "Menor de edad"

**5. Convergencia:** Ambos caminos SE UNEN antes del FIN. Esto es importante: sin importar qué camino tomamos, eventualmente llegamos al mismo punto de terminación.

**Detalles técnicos:**
- Las etiquetas "Sí" y "No" DEBEN estar visibles para claridad
- Los dos caminos del rombo deben estar claramente separados
- La reunificación de caminos se hace con flechas que convergen

**Error común:** No reunir los caminos. Algunos estudiantes ponen dos símbolos FIN (uno por camino). Funcionalmente puede estar bien, pero es menos elegante.

**Actividad:** Ejecutá el diagrama con tres valores: 15 (menor), 18 (límite), 25 (mayor). Que los estudiantes vean cómo cada valor toma un camino diferente.

**Pregunta avanzada:** "¿Qué pasaría si queremos distinguir tres categorías: menor (< 13), adolescente (13-17), adulto (>=18)?" Esto requerirá dos rombos anidados o encadenados (lo verán más adelante).
-->

# Contar del 1 al 5

**Problema:**
* Mostrar los números del 1 al 5

**Diagrama:**
* CON decisión
* CON lazo (repetición)
* Flujo vuelve hacia atrás

<!--
Este tercer ejemplo introduce **lazos** o **bucles**: estructuras que permiten repetir acciones.

**Estructura del problema:**
- Necesitamos mostrar: 1, 2, 3, 4, 5
- Sin lazo: necesitaríamos 5 bloques "Mostrar número"
- Con lazo: un solo bloque "Mostrar" que se ejecuta 5 veces

**Concepto clave del lazo:**
1. **Inicialización:** contador = 1
2. **Condición:** ¿contador <= 5?
3. **Cuerpo del lazo:** mostrar contador
4. **Actualización:** contador = contador + 1
5. **Repetir** desde paso 2

**Novedad visual:** Por primera vez veremos una flecha que va HACIA ARRIBA. Esto representa la repetición: volver a evaluar la condición.

**Correspondencia con Python:** Este diagrama se traduce a un lazo `while` o `for`.

**Pregunta reflexiva:** "Si quitamos la línea 'contador = contador + 1', ¿qué pasaría?" (Respuesta: lazo infinito, siempre mostraría 1). Esto introduce el concepto de condición de terminación y por qué debemos actualizar el contador.

El siguiente slide muestra el diagrama completo, que es más complejo pero muy importante dominar.
-->
* CON decisión
* CON lazo (repetición)
* Flecha que vuelve atrás

<!-- _class: code -->

# Diagrama: Contar del 1 al 5

```
    ╭─────────╮
    │ INICIO  │
    ╰─────────╯
         │
  ┌──────────────┐
  │ contador = 1 │
  └──────────────┘
         │
    ┌────↓────┐
    │   ╱╲    │
    │  ╱  ╲   │
    │ ╱cont╲  │
    │╱ <=5? ╲ │
    │────────│←┘
   Sí│      │No
     │      │
  Mostrar  FIN
  contador
     │
  contador
   = cont+1
     │
     └──→(vuelve arriba)
```

<!--
Este es el diagrama más complejo hasta ahora. Analicémoslo cuidadosamente:

**1. INICIO → contador = 1 (inicialización):** Antes de entrar al lazo, inicializamos la variable de control. Esto es CRUCIAL: sin inicialización, `contador` tendría un valor indefinido.

**2. Rombo (contador <= 5?):** Esta es la **condición del lazo**. Se evalúa ANTES de cada iteración:
   - Si Sí (contador <= 5): ejecutamos el cuerpo del lazo
   - Si No (contador > 5): salimos del lazo hacia FIN

**3. Cuerpo del lazo (Sí):**
   - Mostrar contador (imprime el valor actual)
   - contador = contador + 1 (incrementamos el contador)

**4. Flecha hacia arriba:** Después de incrementar, VOLVEMOS al rombo para reevaluar la condición. Esta es la característica definitoria de un lazo.

**Ejecución paso a paso:**
- Iteración 1: contador=1, ¿1<=5? Sí, muestra 1, contador→2, vuelve
- Iteración 2: contador=2, ¿2<=5? Sí, muestra 2, contador→3, vuelve
- ...
- Iteración 5: contador=5, ¿5<=5? Sí, muestra 5, contador→6, vuelve
- Iteración 6: contador=6, ¿6<=5? No, sale al FIN

**Errores comunes:**
1. Olvidar inicializar contador → valor indefinido
2. Olvidar incrementar contador → lazo infinito
3. Condición incorrecta (ej: `< 5` en vez de `<= 5`) → solo muestra del 1 al 4

**Actividad recomendada:** Hacé una "ejecución en seco" en la pizarra, escribiendo el valor de `contador` en cada iteración. Los estudiantes deben ver físicamente cómo cambia el estado.

**Pregunta desafiante:** "¿Cómo modificarías este diagrama para contar del 10 al 1 (hacia atrás)?" (Respuesta: contador=10, condición `contador>=1`, incremento `contador-1`).
-->

<!-- _header: 'Tips' -->

# Consejos para diagramas

**Hacelo simple:**
* Un proceso por rectángulo
* Una pregunta por rombo

**Mantené orden:**
* De arriba hacia abajo
* De izquierda a derecha

**Evitá:**
* Flechas que se cruzan
* Textos largos dentro de símbolos

<!--
Estos son principios de **diseño de diagramas** que distinguen un diagrama amateur de uno profesional:

**Simplicidad:**
- **Un proceso por rectángulo:** No pongas "Leer a, b, c, calcular suma, mostrar resultado" en un solo rectángulo. Cada acción merece su símbolo.
- **Una pregunta por rombo:** Un rombo debe evaluar UNA condición. Si necesitás evaluar múltiples condiciones, usá múltiples rombos o combinalas con operadores lógicos.

**Orden:**
- **Arriba → Abajo:** El flujo principal siempre va hacia abajo. Esto hace que sea natural seguir el diagrama con la mirada.
- **Izquierda → Derecha:** Los caminos alternativos (ej: rama "No" de un if) van hacia la derecha o izquierda del flujo principal.

**Evitar:**
- **Cruces de flechas:** Indican que el diagrama está mal organizado. Reorganizá los símbolos para eliminar cruces.
- **Textos largos:** Si no cabe en el símbolo, el texto es demasiado detallado. Sintetizá: en vez de "Leer el primer número ingresado por el usuario", poné "Leer numero1".

**Principio general:** Un buen diagrama debe ser entendible en 30 segundos de vistazo. Si requiere 5 minutos de análisis, está mal diseñado.

**Analogía:** Los diagramas son como las señales de tránsito: simples, claros, universales. No son ensayos literarios.
-->

# Ejercicio: Número positivo o negativo

**Problema:**
* Leer un número
* Decir si es positivo, negativo o cero

**¿Qué símbolos necesitás?**
* INICIO/FIN (óvalos)
* Leer número (paralelogramo)
* Decisiones (rombos) - ¿cuántos?
* Mostrar resultado (paralelogramos)

<!--
Este ejercicio es el primero que los estudiantes resolverán independientemente. Es desafiante porque requiere **dos decisiones**, no una.

**Análisis del problema:**
- **Entrada:** Un número (puede ser entero o decimal)
- **Salida:** Uno de tres mensajes: "Positivo", "Negativo", o "Cero"
- **Lógica:** Tres casos mutuamente excluyentes

**Pistas sutiles sin dar la solución:**
- Preguntá: "¿Un solo rombo puede tener 3 opciones?" (No, solo 2)
- Entonces: "¿Cuántos rombos necesitamos para distinguir 3 casos?" (Al menos 2)

**Estrategias posibles:**
1. **Secuencial:** `¿> 0?` → Sí: "Positivo" | No: `¿< 0?` → Sí: "Negativo" | No: "Cero"
2. **Anidada:** Primero `¿= 0?` → Sí: "Cero" | No: `¿> 0?` → Sí: "Positivo" | No: "Negativo"

Ambas son válidas. Lo importante es que la lógica cubra los tres casos sin ambigüedades.

**Tiempo sugerido:** 7-10 minutos. Circulá por el aula observando los intentos. Si ves errores comunes, tomá nota para discutirlos después.

No avances al siguiente slide hasta que la mayoría haya intentado una solución.

**Símbolos:**
* Óvalo = Inicio/Fin
* Paralelogramo = Entrada/Salida
